# מערכת זימון אסיפות הורים – ישיבת שבילי התורה

הורים קובעים תור לאסיפת הורים עם מספר תעודת הזהות של התלמיד. רבנים פותחים שעות קבלה ומנהלים את התורים שלהם, וההנהלה מנהלת תלמידים, רבנים, אסיפות, דוחות והגדרות.

- **ממשק:** אתר סטטי (HTML, CSS ו-JavaScript מודולרי) שמתפרסם ב-GitHub Pages. אין שרת Node.
- **שרת ומסד נתונים:** ‏Supabase, כלומר PostgreSQL עם RLS, ‏Auth לאנשי צוות ו-Edge Functions.
- **תאריכים:** כל תאריך מוצג עם יום בשבוע, תאריך עברי מלא (מחושב ב-`@hebcal/core`) ותאריך לועזי, לדוגמה: *יום חמישי, ד׳ בחשוון תשפ״ז (15.10.2026)*.

  js/pages/             קוד לכל דף

### עקרונות אבטחה

| נושא | מימוש |
|---|---|
| גישה אנונימית | אין הרשאת קריאה לאף טבלה. ההורים עובדים רק דרך Edge Function ‏`parent`. |
| הורים | הזיהוי מחזיר token לסשן של 30 דקות (נשמר כ-hash). ההורה רואה רק שם, כיתה, שם הרב ואסיפות פתוחות, בלי הערות ובלי מספר זהות. |
| רבנים | ‏RLS: רב רואה רק את התלמידים, הסלוטים, התורים וההערות שלו. מספרי זהות – רק של התלמידים שלו, דרך פונקציה ייעודית. |
| כתיבה | כל כתיבה עוברת דרך פונקציות `SECURITY DEFINER` שבודקות תפקיד בצד השרת. אין כתיבה ישירה לטבלאות. |
| הזמנה אטומית | נעילת שורת הסלוט (`FOR UPDATE`) ואינדקסים ייחודיים חלקיים. כששני הורים מנסים לתפוס את אותה שעה, רק אחד מצליח, והשני מקבל "השעה נתפסה, בחרו שעה אחרת". |
| חפיפות | ‏`EXCLUDE USING gist` על טווחי זמן לחלונות זמינות ולסלוטים. |
| כניסת צוות | מספר זהות וסיסמה. ה-Edge Function ממפה את מספר הזהות למשתמש Auth בצד השרת. כתובת המייל הפנימית לא נחשפת. נעילה אחרי 5 כישלונות. |
| קודים אישיים | ‏4 ספרות שנוצרות במחולל קריפטוגרפי בשרת ונשמרות כ-bcrypt hash. |
| הגבלת קצב | לפי IP (כ-hash) ולפי תלמיד. ניסיונות חשודים נרשמים ב-`security_events`. |
| יומן | ‏`audit_logs` לכל שינוי, בלי מספרי זהות מלאים ובלי תוכן הערות. |
| סודות | אין סודות בקוד. ב-`config.js` יש רק מפתח publishable, שמותר שיהיה בדפדפן. |

> ⚠️ **כניסה עם מספר זהות בלבד אינה הזדהות בטוחה.** כל מי שיודע את מספר הזהות של תלמיד יכול לראות את שמו, כיתתו והרב שלו ולקבוע לו תור. לכן מומלץ להפעיל **קוד אישי** (ניהול ← קודים אישיים) לפני שמכניסים נתוני אמת. גם קוד בן 4 ספרות חלש יחסית, ולכן המערכת מגבילה ניסיונות ומתעדת אותם.

## הקמה, שלב אחרי שלב

### 1. Supabase

הפרויקט `shvilei-torah-meetings` כבר נוצר (אזור eu-central-1), ושלושת ה-Edge Functions כבר פרוסים בו.

אם מקימים פרויקט חדש מאפס:
1. נכנסים ל-https://supabase.com, יוצרים פרויקט חדש ושומרים את סיסמת המסד.
2. ‏**SQL Editor** ← מדביקים את `supabase/migrations/20261015000001_schema.sql` ← **Run**.
3. ‏**SQL Editor** ← מדביקים את `supabase/setup_functions_and_grants.sql` ← **Run**.
   אחריו מריצים באותו אופן את `supabase/migrations/20261015000004_class_teacher.sql` ואת `20261015000005_teacher_conferences.sql`.
4. פורסים את הפונקציות עם Supabase CLI:
   ```bash
   npx supabase login
   npx supabase link --project-ref <PROJECT_REF>
   npx supabase functions deploy parent --no-verify-jwt
   npx supabase functions deploy staff-login --no-verify-jwt
   npx supabase functions deploy admin-staff --no-verify-jwt
   ```

### 2. Secrets לפונקציות

ב-Supabase: ‏**Project Settings ← Edge Functions ← Secrets**:

| שם | ערך |
|---|---|
| `ALLOWED_ORIGINS` | כתובת האתר, למשל `https://nechberman.github.io` |
| `IP_HASH_SALT` | מחרוזת אקראית ארוכה |
| `BOOTSTRAP_TOKEN` | מחרוזת אקראית של 20 תווים לפחות. משמשת פעם אחת ליצירת המנהל הראשון. |

את `SUPABASE_URL` ואת `SUPABASE_SERVICE_ROLE_KEY` ‏Supabase מגדיר אוטומטית. **לעולם לא מעתיקים את ה-service role key לקוד או ל-GitHub.**

### 3. הגדרות Auth

**Authentication ← Sign In / Providers:**
- לכבות **Allow new users to sign up**. אנשי צוות נוצרים רק על ידי מנהל.
- **Minimum password length**: ‏10.

### 4. כתובת ומפתח בקובץ `web/config.js`

```js
window.APP_CONFIG = {
  SUPABASE_URL: 'https://<PROJECT_REF>.supabase.co',
  SUPABASE_PUBLISHABLE_KEY: 'sb_publishable_...',
};
```
את המפתח מוצאים ב-**Project Settings ← API Keys ← Publishable key**. זה מפתח ציבורי ומותר להציג אותו.

### 5. GitHub Pages

כל push לענף `main` מריץ את `.github/workflows/ci-pages.yml`: ‏lint, ‏typecheck, בדיקות, build ופרסום.
אם Pages עוד לא פעיל: ‏**Settings ← Pages ← Source: GitHub Actions**.

### 6. מנהל ראשון

1. פותחים `https://<user>.github.io/shvilei-torah-meetings/setup.html`.
2. מזינים את `BOOTSTRAP_TOKEN`, שם, מספר זהות וסיסמה חזקה.
3. אחרי היצירה הדף נסגר לצמיתות, כי כבר קיים מנהל. מומלץ למחוק את ה-secret ‏`BOOTSTRAP_TOKEN`.

### 7. בדיקת זרימה מלאה עם נתוני דמה (לפני נתוני אמת)

1. מנהל: ‏**רבנים וצוות** ← הוספת רב. ‏**כיתות** ← כיתה חדשה. ‏**יבוא תלמידים** ← קובץ דוגמה.
2. ‏**אסיפות** ← אסיפה חדשה ← שיוך רבנים.
3. הרב נכנס ← "הוספת חלון זמינות" (לדוגמה 17:00–20:00) ← בודק שנוצרו תורים.
4. מנהל ← "פתיחה להרשמה".
5. הורה, בנייד: מזין מספר זהות של תלמיד דמה ← בוחר יום ושעה ← מאשר.
6. הרב: "דוח להדפסה" ← בודק עברית, יישור לימין ושבירת עמודים.
7. מנהל: מעביר תור לשעה אחרת ← סוגר את האסיפה ← מעביר לארכיון.
8. ‏**קודים אישיים**: יצירה גורפת ← הפעלה ← בדיקה שאי אפשר להיכנס בלי קוד.

## שימוש יומיומי – תשובות מהירות

- **שיוך רב לכיתה:** ניהול ← "כיתות ורבנים" ← "עריכה ושיוך רב". אפשר להעביר בבת אחת את כל תלמידי הכיתה. תלמיד עם תור פעיל לא מועבר אוטומטית.
- **שעות האסיפה:** "זמינות ותורים" (מנהל) או "התורים שלי" (רב) ← "הוספת חלון זמינות": בוחרים יום, משעה–עד שעה, וכל כמה דקות תור (למשל רבע שעה). הפסקה: "הוספת הפסקה".
- **שיבוץ טלפוני:** בטבלת התלמידים שמתחת ללוח – "קביעת תור" ליד תלמיד שטרם נרשם (כשהאסיפה פתוחה). שינוי/ביטול – מלוח התורים.
- **הרב והתלמידים שלו:** אזור הרב ← "התלמידים שלי": רשימה עם מספרי זהות, הוספה ועריכה (רק בכיתות שמשויכות אליו).
- **רב פותח אסיפה בעצמו:** אזור הרב ← "אסיפת הורים חדשה". הרב מנהל (עריכה, פתיחה, סגירה, מחיקה) רק אסיפות שהוא פתח. המנהל רואה ומנהל הכול.
- **מחיקת תלמיד:** אפשרית רק לתלמיד בלי תורים קודמים; אחרת מסמנים "לא פעיל".
- **מחיקת אסיפה:** "אסיפות" ← "מחיקה" (דורש להקליד את שם האסיפה; מוחק לצמיתות גם את התורים). לשמירת היסטוריה עדיף "העברה לארכיון".

## מדיניות

- **תאריך עברי:** תורים נקבעים לפי היום האזרחי המקומי (Asia/Jerusalem), ומוצג התאריך העברי של אותו יום. התאריך לא מתחלף בשקיעה, כי אסיפות ערב שייכות ליום האזרחי שבו הן מתקיימות. אם יידרשו תורים אחרי השקיעה עם תאריך עברי של היום הבא, צריך לשנות את `hebrewLabel` ב-`web/js/lib/dates.js`.
- **הערות פנימיות:** גלויות רק לרב שכתב אותן ולהנהלה, ולעולם לא להורים. מומלץ למחוק פעם בשנה (ניהול ← הגדרות ← "מחיקת הערות בנות יותר משנה").
- **שימור:** אסיפות בארכיון נשמרות לצפייה. סשנים של הורים נמחקים אחרי 30 דקות. אירועי אבטחה נמחקים אחרי 180 יום.
- **מחיקת תלמיד:** במקום מחיקה מסמנים "לא פעיל", כדי לשמור את היסטוריית התורים.

## גיבוי ושחזור

- ‏Supabase בתוכנית החינמית שומר גיבוי יומי ל-7 ימים (Database ← Backups).
- גיבוי ידני: ‏`npx supabase db dump --linked -f backup.sql` (וגם `--data-only` לנתונים בלבד).
- שחזור: מדביקים את הקובץ ב-SQL Editor של פרויקט חדש, או מריצים `psql "<connection string>" -f backup.sql`.
- מומלץ גם לייצא מדי פעם "תלמידים ← יצוא ל-Excel".

## תחזוקה

- **פרויקט מושהה:** ‏Supabase בחינם משהה פרויקט אחרי 7 ימים בלי פעילות. ה-workflow ‏`keep-alive.yml` פונה לשרת פעם ביום כדי למנוע את זה. ‏GitHub מכבה workflow מתוזמן ב-repository שלא שונה 60 יום, ואז מגיע מייל ומספיק ללחוץ בו Enable. אם הפרויקט בכל זאת הושהה: ‏Dashboard ← ‏**Resume project**.

- **לוגו:** מעלים קובץ ל-`web/assets/` ומגדירים בהגדרות `./assets/logo.png`.
- **קישור Waze:** ב-Waze מחפשים את כתובת הישיבה ← שיתוף ← העתקת קישור ← מדביקים בהגדרות.
